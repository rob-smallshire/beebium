# BBC Micro Reset and Break Key

This document describes the reset circuitry and Break key behavior in Beebium.

## Hardware Reset Signals

The BBC Micro has two separate reset signals with different purposes:

| Signal | Source | Triggered By | What It Resets |
|--------|--------|--------------|----------------|
| **RST** | IC16 (NE555 timer) | Break key OR power-up | CPU, most peripherals |
| **RSTA** | R20/D1/C10 RC network | Power-up ONLY | System VIA (IC3) only |

### RST (Reset)

The RST signal is generated by the NE555 timer circuit (IC16) and resets the CPU and most peripherals. It is triggered by:
- Power-on
- The Break key (directly connected to pin 4 of the NE555)

### RSTA (Reset A)

The RSTA signal is generated by an RC network and resets **only** the System VIA. Critically, it is triggered **only** at power-on, not by the Break key. This distinction allows the MOS to detect whether a reset was caused by power-on or by the Break key.

## Reset Types in Beebium

Beebium emulates two hardware-level reset types:

### Break Reset (soft_reset)

Triggered by: Break key release

Effects:
- Asserts RST signal (resets CPU and most peripherals)
- Does **not** assert RSTA (System VIA state preserved)
- Does **not** clear RAM

This is implemented as `Machine::soft_reset()` and corresponds to releasing the Break key.

### Power-On Reset (reset)

Triggered by: Power-on / initial machine creation

Effects:
- Asserts both RST and RSTA signals
- Resets CPU and **all** peripherals including System VIA
- Clears RAM to a known state

This is implemented as `Machine::reset()` and corresponds to power cycling the machine.

## How MOS Detects Reset Type

The MOS uses the System VIA's Interrupt Enable Register (IER at $FE4E) to detect reset type:

1. On any reset, MOS examines the System VIA IER
2. If IER shows interrupts disabled (bits 0-6 = 0) → Power-on reset → Full initialization
3. If IER shows interrupts enabled → Break reset → Warm reset (soft reset)

The key insight is that:
- Power-on triggers RSTA, which clears the System VIA including its IER
- Break only triggers RST, which does **not** clear the System VIA

After MOS has configured the VIA during boot, the IER will have interrupts enabled. A subsequent Break reset preserves this state, allowing MOS to detect that it's a warm reset.

### OSBYTE &FD

MOS stores the detected reset type at location $28B, accessible via OSBYTE &FD:
- **0**: Soft reset (Break) - VIA was configured
- **2**: Hard reset (power-on or Ctrl-Break) - VIA was unconfigured

## Ctrl-Break (Hard Reset via Software)

**Important**: The hardware does **not** distinguish between Break and Ctrl-Break. This distinction is made entirely by MOS software.

When Break is released, MOS:
1. Examines the keyboard matrix to check if Ctrl is held
2. If Ctrl is held, MOS clears the System VIA IER before checking it
3. This causes MOS to detect a "cold boot" and perform full initialization

The result is that Ctrl-Break behaves like a power-on reset (OSBYTE &FD returns 2), but the hardware still only performed a Break reset.

## Software Hard Reset Trick

Since MOS detects reset type by checking the VIA IER, you can trick MOS into performing a full initialization:

```basic
?&FE4E = 127
```

This writes 127 (0x7F) to the VIA IER, which clears all interrupt enable bits (writing with bit 7 = 0 clears the specified bits). When you subsequently press Break:

1. Hardware does a Break reset (preserves VIA state)
2. VIA IER is still 0 (we cleared it, Break didn't change it)
3. MOS sees "unconfigured" VIA → performs full "cold boot" initialization

This is useful for forcing a hard reset without holding Ctrl.

## Break Key Timing

The Break key is **not** part of the keyboard matrix. It is directly connected to the reset circuit via pin 4 of the NE555 timer.

### While Break is Held

- The reset line is held low
- The CPU is halted (cannot execute instructions)
- All peripherals are held in reset state

### On Break Release

1. The reset line goes high
2. The 6502 executes its 7-cycle reset sequence
3. The CPU loads PC from the reset vector ($FFFC/$FFFD)
4. MOS begins its reset detection and initialization routine

### Modifier Detection

MOS checks modifier keys (Ctrl, Shift) at the moment of Break release, not when Break is pressed. This means:

- Press Break, then press Ctrl, then release Break → MOS detects Ctrl-Break
- Press Ctrl+Break together, release Ctrl, then release Break → MOS detects plain Break

## Shift-Break (Auto-Boot)

When the auto-boot keyboard link is made (bit 3 = 0 in startup options), pressing Shift-Break causes MOS to attempt to load and run a `!Boot` file from the current filing system.

See [keyboard.md](keyboard.md) for details on keyboard links.

## API

### C++ Machine API

```cpp
// Power-on reset (clears everything including RAM)
void reset();

// Break reset (preserves System VIA state)
void soft_reset();

// Break key control
void break_down();      // Hold Break (halt CPU)
void break_up();        // Release Break (triggers soft_reset)
bool is_in_reset();     // True if Break is currently held
```

### gRPC API (KeyboardService)

```protobuf
// Hold Break key (halt CPU)
rpc BreakDown(BreakDownRequest) returns (BreakDownResponse);

// Release Break key (begin soft reset)
rpc BreakUp(BreakUpRequest) returns (BreakUpResponse);

// Query Break key state
rpc GetBreakState(GetBreakStateRequest) returns (BreakKeyState);

message BreakKeyState {
    bool is_held = 1;  // True if Break key is currently held
}
```

### Python API

```python
# Break key operations
bbc.keyboard.break_down()      # Hold Break (halts CPU)
bbc.keyboard.break_up()        # Release Break (triggers soft reset)
bbc.keyboard.is_break_held()   # Check if Break is currently held
bbc.keyboard.press_break()     # Convenience: down + up
bbc.keyboard.ctrl_break()      # Convenience: Ctrl-Break sequence
bbc.keyboard.shift_break()     # Convenience: Shift-Break (auto-boot)
```

The convenience methods hold keys for **emulated** time (`hold_time`, and
`shift_break`'s `shift_hold_after`, are emulated seconds): they poll the cycle
count while the machine runs, so the machine sees the same press however fast
the host runs it. They need a running machine and raise `DebuggerError` on a
stopped one. To press Break on a stopped machine, use `break_down()` and
`break_up()` and advance time yourself.

## Summary

| Reset Type | Trigger | RST | RSTA | Clears VIA | Clears RAM | MOS Detection |
|------------|---------|-----|------|------------|------------|---------------|
| Break | Break key | Yes | No | No | No | OSBYTE &FD = 0 |
| Power-On | Power cycle | Yes | Yes | Yes | Yes | OSBYTE &FD = 2 |
| Ctrl-Break | Break + Ctrl | Yes | No | By MOS | No | OSBYTE &FD = 2 |
| Software trick | ?&FE4E=127 + Break | Yes | No | By user | No | OSBYTE &FD = 2 |
